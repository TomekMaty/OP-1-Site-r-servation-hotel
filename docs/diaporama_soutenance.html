Contexte & objectif

Pourquoi ce projet ?

  • Contexte : un hôtel a besoin d'outils numériques pour gérer clients, chambres, commandes et réseau WiFi
  • Objectif : concevoir et déployer une solution complète, fonctionnelle et démontrable sur le réseau de l'école
  • Contrainte : tout tourne sur un seul PC via Docker — aucune installation manuelle de PHP, MySQL ou FreeRADIUS
  • Sécurité : le WiFi n'est accessible qu'après authentification par numéro de chambre (protocole RADIUS)
Besoins couverts
Côté client
Réserver en ligne · Commander un repas · Accéder au WiFi avec son numéro de chambre · Voir son espace personnel
Côté admin
Voir les réservations · Gérer les commandes · Surveiller le WiFi · Recevoir des alertes Telegram en temps réel

FreeRADIUS + Remontée admin

Sessions WiFi dans l'admin

  • FreeRADIUS dans Docker — 10 chambres (101–603) configurées, secret partagé avec la borne
  • Relay UDP PowerShell — contourne la limitation Docker Desktop Windows : écoute sur :18120, retransmet vers FreeRADIUS :1812
  • Script sync_radius_sessions.sh — parse les logs FreeRADIUS, insère/met à jour dans MySQL (idempotent : sans doublons)
  • Onglet WiFi de l'admin — appareils connectés, chambres, adresses MAC, Access-Accept/Reject
  • Activité réseau — section de démonstration honnêtement labelisée (domaines DNS consultés)
Données WiFi en base (réelles)
4 sessions · 3 Access-Accept · 1 Reject · Adresses MAC réelles d'appareils testés
Activité réseau (démo)
10 lignes DNS · Chambres 101 et 201 · Clairement marquées "démonstration" dans l'interface
💻 Démo : bash sync_radius_sessions.sh → admin WiFi mis à jour
À dire à l'oral
"Un script bash lit les logs FreeRADIUS et les transforme en données SQL. L'admin voit en temps réel quels appareils sont connectés, depuis quelle chambre et avec quel statut. Le script peut être relancé autant de fois qu'on veut sans créer de doublons."

Sécurité & problèmes résolus

Difficultés et solutions

Mesures de sécurité appliquées
JWT HS256
Tokens signés et vérifiés à chaque requête — impossible à forger sans le secret
Mots de passe bcrypt
Jamais stockés en clair — hash bcrypt irréversible en base MySQL
Requêtes préparées PDO
Paramètres bindés — protection totale contre les injections SQL
Ports restreints
phpMyAdmin + MySQL limités à 127.0.0.1 — inaccessibles depuis le réseau WiFi
Problèmes rencontrés et solutions
Problème 1 — Docker + UDP
Docker Desktop Windows ne peut pas recevoir de paquets UDP depuis le réseau local (NAT Docker)
Solution
Relay UDP PowerShell : écoute sur 192.168.30.104:18120 et retransmet vers FreeRADIUS sur 127.0.0.1:1812
Problème 2 — Double réservation
Deux clients pouvaient potentiellement réserver la même chambre aux mêmes dates
Solution
Requête SQL avec condition de chevauchement (check_in < sortie AND check_out > arrivée) + attribution automatique
À dire à l'oral
"La principale difficulté était Docker + RADIUS sur Windows. On a résolu ça avec un relay UDP maison en PowerShell. C'est une solution non standard, mais stable et documentée."
